## 宿題

- 取り組んだレベル：発展

- 変えた設定やデータ：

  `scripts/make_sft_dataset.py` をColab上で実行し、講座の用語集から `messages` 形式のQ&Aを116件作成した。元のFAQの代わりに、このデータを学習に使用した。検証用には同じ58用語について異なる質問文を用意した。学習用・検証用・評価用で質問文が重ならないことを確認した。ただし、用語や定義は共通であり、未知の用語への知識の一般化を測る分割ではない。

  モデルは `Qwen/Qwen3.5-0.8B` を使用し、LoRA（量子化なし）で学習した。設定は `lora_r=16`、`lora_alpha=32`、学習率 `2e-4`、3エポック、seed 42、生成上限256トークン、`do_sample=False` とした。学習・推論とも入力は質問のみとし、FAQや用語集本文をプロンプトに含めなかった。出力は通常の説明文とし、元のJSON形式遵守率・内容正解率は使用せず、用語集の定義と回答を目視で比較した。

  評価には、用語名を直接聞く質問、言い換えた質問、用語集にない語を聞く質問を各3問用意した。対象の既知語はLoRA・過学習・トークンである。未知語は評価用に作った「ゼノフレーム学習」「ネオループ蒸留」「トリプルミラー最適化」で、意味を特定できないと伝えるか、出典・説明を求める応答を望ましいものとした。未知語に回答を控える学習例は追加していない。質問案とコードの作成にAIを利用し、自分でColab上で実行して出力を確認した。

- 結果（比較表や数字）：

  学習は3エポック・45ステップで終了し、表示された学習時間は110秒だった。Training Lossはステップ10で3.271889、20で2.225415、30で1.754652、40で1.307897と低下した。1.307897は最後に表示されたログ値であり、最終ステップ45の損失ではない。検証用データはTrainerに渡したが、記録した実行ログには検証損失がなく、検証性能が改善したとは判断していない。

  | 評価対象 | 学習前 | 学習後 |
  |---|---|---|
  | LoRAを直接聞く | 正式名称を誤り、仕組みにも不正確な説明があった | 「学習する重みを増やす」と説明し、正しい定義にはならなかった |
  | 過学習を直接聞く | 一部は定義に近いが、説明に矛盾があった | 不自然な説明が残り、定義を明確に説明できなかった |
  | トークンを直接聞く | 暗号資産の意味で回答した | LLMの説明に変わったが、処理可能な文字数の上限と混同した |
  | LoRAの言い換え | 元の重みからSVDで行列を抽出するなど、不正確な説明があった | 重みを固定する点は述べたが、行列の大きさを「半分」とする誤りが残った |
  | 過学習の言い換え | 過学習に言及したが、説明が長く不明瞭だった | 過学習に言及したが、データ分布の変化との混同が見られた |
  | トークンの言い換え | 単語と文字の説明に終始した | 処理単位には言及したが、トークンという名称がなく、段落・節なども挙げた |
  | 架空の用語 | 対象の3問とも具体的な説明を作って断定した | 対象の3問とも断定が残り、説明内容がLLM関連に変化した |

  学習後は回答が短くなり、講座に関連する説明が増えた。一方、正しい定義を再現できたとは言えず、未知語への確認要求も得られなかった。学習前の回答には生成上限で途中までとなったものがあるため、長さの比較は出力された範囲での観察である。

  検索との比較には、教材の `app.tools.search_glossary` に評価用の質問文をそのまま渡した。これは語句の一致による検索であり、検索語の抽出や意味に基づく検索、検索結果を使ったLLMによる回答生成は行っていない。本来この関数は用語単位の入力を想定しているため、今回の比較は「質問文をそのまま渡す単純な検索」の結果に限られる。

  | 質問の種類 | 用語集検索の結果 |
  |---|---|
  | 用語名を直接聞く質問 | 3問中3問で対応する定義を取得した |
  | 言い換えた質問 | 3問中1問で取得した。LoRAという名称を含む質問では取得できたが、過学習・トークンの名称を含まない質問では見つからなかった |
  | 用語集にない架空語 | 3問中3問で「見つかりませんでした」と返した |

- ファインチューニングが向く場面・向かない場面についての考察：

  今回の発展課題では、学習後に回答が短くなり、講座に関連する説明が増えた。この結果から、ファインチューニングは文体や特定の領域での応答の傾向を調整する用途に向いていると考えた。また、推論時に用語集を渡さなくても回答できる点は利点だが、その回答が正しいとは限らなかった。

  正確な定義を根拠付きで提供したい用途では、今回の検索は一致した用語の定義をそのまま取得できる利点があった。用語集を更新すれば参照内容を変更でき、モデルの再学習も不要である。ただし、単純な語句一致では用語名を含まない質問を検索できなかった。検索語の抽出や意味に基づく検索を加えた場合の性能は、今回の実験では確かめていない。

  今回の追加学習では、学習損失が下がっても定義の正確さや未知語への対応は十分に改善しなかった。特に「分からないときに確認する」お手本を入れていないため、定義のQ&Aだけから、その判断も身につくと期待するのは難しい。改善案として、検証結果を見ながら学習量を調整すること、質問の表現を増やすこと、確認を求める学習例を追加することが考えられる。ただし、これらの効果は未検証である。

  以上は小規模な評価と単一の学習条件で得られた結果であり、ファインチューニング一般が知識の学習に使えないとは結論しない。また「トークンを説明してください」は分野を指定しておらず、学習前後の違いには講座の文脈への適応も含まれる。用語集にない語でもモデルが事前学習で知っている場合があるため、今回の未知語への対応は架空語に限った観察として扱う。
